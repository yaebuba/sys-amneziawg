# sys-amneziawg : dns.mitm host redirection
#
# Two jobs, and the first one matters more than the second.
#
# 1. Nintendo's telemetry endpoints stay blocked. Atmosphere adds these by
#    default, but a hosts file of our own is exactly the situation where that
#    protection gets lost by accident, so they are written out explicitly.
#    Do not remove them.
#
#    Note that sys-amneziawg listens on 127.0.0.1:443, so these names now
#    reach a port that answers. The module refuses them by name - see the
#    deny list in awg_proxy.c - and counts them as deny= in the log. The
#    block holds, but it holds because of that list, not because the address
#    goes nowhere.
#
# 2. The hostnames sys-amneziawg proxies point at 127.0.0.1, where the module
#    is listening. It reads the name out of the TLS ClientHello and opens the
#    real connection through the tunnel.
#
# Loopback is deliberate. The console's own LAN address used to go here, and
# it was wrong twice over: it changes with the network - a new DHCP lease,
# the dock's wired link, a phone hotspot - and while the module was bound to
# it, anything else on the same Wi-Fi could use the console as an open proxy
# into the tunnel. 127.0.0.1 is the same everywhere and reachable only from
# the console itself. Nothing here needs editing when the network changes.

# --- Nintendo telemetry: leave this alone ---
127.0.0.1 receive-lp1.dg.srv.nintendo.net
127.0.0.1 receive-lp1.er.srv.nintendo.net

# --- proxied through the tunnel ---
127.0.0.1 github.com
