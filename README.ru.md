# sys-amneziawg

[English](README.md) · Русский

Клиент AmneziaWG для Nintendo Switch в виде системного модуля Atmosphère.
Принимает конфигурацию, выгруженную из клиента AmneziaVPN, и направляет через
этот туннель перечисленные вами имена хостов. Остальной трафик консоли не
затрагивается.

Протокол реализован полностью и проверен против рабочего сервера. Трафик
выбирается по именам хостов; системный перехват сокетов не реализован.

По всем вопросам — [t.me/oneth1nq](https://t.me/oneth1nq): там же выходят
заметки о релизах.

## Как это устроено

`dns.mitm` из Atmosphère отвечает на перечисленные имена адресом `127.0.0.1`.
Приложение открывает обычное, с его точки зрения, соединение, а модуль
принимает его на порту 443. Дальше модуль читает имя хоста из TLS ClientHello,
резолвит его внутри туннеля, соединяется с настоящим сервером через lwIP и
AmneziaWG и передаёт данные между ними.

```text
приложение ── TCP/443 ──▶ sys-amneziawg ──▶ lwIP ──▶ AmneziaWG ──▶ сервер
                            читает SNI                 шифрует
```

Для приложения это обычный сокет. Каждый байт между консолью и узлом AmneziaWG
передаётся в зашифрованном виде.

## Что понадобится

- Switch с Atmosphère и доступным `dns.mitm`. Рекомендуется emuMMC.
- Конфигурация AmneziaWG, выгруженная из клиента AmneziaVPN. В поле `Endpoint`
  должен стоять литеральный адрес IPv4 — доменное имя невозможно разрешить до
  того, как поднимется туннель, через который оно и резолвится.

Ничего здесь не зависит от IP-адреса консоли: модуль слушает на петле, а она
одинакова в любой сети. Переход между Wi-Fi, проводным подключением в доке и
раздачей с телефона не требует никаких правок.

Перед установкой любого системного модуля сделайте резервную копию карты.

## Установка

**1. Установите модуль.** Скопируйте собранный `sys-amneziawg.nsp` и
`toolbox.json` на карту и создайте пустой файл автозапуска:

```text
/atmosphere/contents/4200000000000D92/exefs.nsp     <- sys-amneziawg.nsp, переименованный
/atmosphere/contents/4200000000000D92/toolbox.json
/atmosphere/contents/4200000000000D92/flags/boot2.flag
```

`boot2.flag` должен существовать; его содержимое не имеет значения.

**2. Установите конфигурацию туннеля.** В AmneziaVPN выгрузите соединение как
обычный конфиг WireGuard/AmneziaWG и сохраните его как:

```text
/config/sys-amneziawg/awg.conf
```

Все поля, которые читает модуль, и их формат перечислены в `awg.conf.example`.

**3. Перечислите хосты.** Скопируйте `hosts.example.txt` на карту и укажите
нужные имена хостов, каждое — на `127.0.0.1`. Имя файла зависит от того, откуда
вы загружаетесь:

| Среда   | Файл                                 |
| ------- | ------------------------------------ |
| emuMMC  | `/atmosphere/hosts/emummc_<ID>.txt`  |
| sysNAND | `/atmosphere/hosts/default.txt`      |

`<ID>` — значение поля `id` из `/emuMMC/emummc.ini` без префикса `0x`.
Atmosphère использует первый подходящий файл, поэтому не оставляйте рядом
конфликтующие варианты.

Сохраните строки телеметрии Nintendo из примера. Atmosphère блокирует
телеметрию по умолчанию, но именно собственный hosts-файл обычно эту защиту и
отключает. Эти строки тоже указывают на `127.0.0.1`, то есть на порт, который
теперь отвечает, — модуль отклоняет имена Nintendo по названию и считает их
как `deny=` в логе, так что блокировка продолжает работать.

**4. Отключите сеть в режиме ожидания.** В **Настройках → Режим ожидания**
выключите **Поддерживать проводную связь в режиме ожидания**. Сегодня ничего не
сломается, если оставить включённой, но в разделе [Сон и док](#сон-и-док)
объяснено, почему привычку стоит завести уже сейчас.

**5. Перезагрузитесь.** Модуль ждёт 15 секунд, чтобы не мешать загрузке,
дожидается сети, поднимает туннель и начинает писать лог.

## Проверка работы

Лог лежит в `/config/sys-amneziawg/sys-amneziawg.log` и создаётся заново при
каждой загрузке, так что сохраните копию заранее, если она нужна. Нормальный
запуск выглядит так:

```text
boot: network up
console ip: 192.168.1.10
endpoint: 203.0.113.10:51820
timers: rekey 120s, keepalive 30s, retry 7s

[  0s] handshake initial attempt 1: sendto=1261 errno=0
[  0s] session up (handshake #1, rekeys 0)
[  0s] lwip interface up on the tunnel
[  0s] proxy listening on 127.0.0.1:443
        proxy: raw.githubusercontent.com
[ 15s] up=14s tx=1137 rx=1952 ka=0 fetches 1/1 | proxy conns=2 ok=1 fail=0 closed=1 live=0/16 deny=0 full=0 idle=0 up=2KB down=1978KB loops=152 stray=0 replay=0 rebuilds=0 sleep=0
        rate 169KB/s (129 pkt/s) | tcp xmit=1137 recv=1952 drop=0 memerr=0 | ip drop=0 | pbuf err=0
[ 17s] power transition (#1) - dropping the tunnel
[112s] tunnel rebuilt (#2) - new socket, handshaking again
[113s] power transition - tunnel already down, leaving it to the rebuild
[119s] session up (handshake #1, rekeys 0)
```

| Запись                     | Что означает                                                            |
| -------------------------- | ------------------------------------------------------------------------ |
| `console ip:`              | Собственный адрес консоли в локальной сети. Справочно; прокси его не использует. |
| `session up`               | Хендшейк AmneziaWG прошёл успешно.                                       |
| `proxy listening on 127.0.0.1:443` | Прокси принимает соединения от консоли.                          |
| `proxy: <хост>`            | Имя хоста, прочитанное из TLS ClientHello и отправленное в туннель.      |
| `up= tx= rx= ka=`          | Возраст сессии в секундах, затем отправленные и принятые пакеты туннеля и keepalive. |
| `fetches N/M`              | Встроенная проверка живости: N из M тестовых HTTP-запросов через туннель прошли. |
| `conns / ok / fail / closed` | Проксированных соединений принято, завершено штатно, не дошло до сервера и закрыто по любой другой причине. Четыре числа сходятся в сумме. |
| `live=N/16`                | Занятых слотов. Таблица фиксированная; при 16/16 новые соединения отклоняются. |
| `deny / full / idle`       | Отклонено по имени (телеметрия Nintendo), отклонено из-за переполнения таблицы и освобождено после простоя. |
| `up=KB down=KB`            | Трафик, прошедший через прокси. Самый наглядный признак того, что данные идут. |
| `rate`                     | Текущая скорость. Около 200 КБ/с — норма.                                |
| `drop / memerr / pbuf err` | Должны оставаться нулями. Иначе стеку не хватает буферов.                 |
| `stray=N`                  | Датаграммы, пришедшие не от настроенного сервера, и отброшенные. Должно оставаться нулём. |
| `replay=N`                 | Подлинные датаграммы, отклонённые потому, что новизну их счётчика доказать не удалось. Несколько штук за длинную сессию — обычное дело; на каждую пишется строка `replay:`, где сказано, дубликат это или пакет, опоздавший настолько, что судить уже нельзя. |
| `rebuilds=N` / `sleep=N`   | Пересозданий туннеля и замеченных снов. Оба растут при обычной работе — см. ниже. |
| `tunnel socket died`       | Сокет перестал работать: сон, обрыв Wi-Fi или перевод в док. Модуль сам пересоздаёт его и заново проводит хендшейк. |
| `power transition`         | Консоль уснула. Туннель разрывается, ключи затираются — ни одна сессия не переживает сон. Если туннель уже лежал, в логе так и написано, и им займётся пересоздание. |
| `no network for Ns`        | Отправка отклонялась из-за отсутствия связи. Через тридцать секунд модуль тратит одно пересоздание, чтобы исключить сокет, который уже не заработает. |

Строка состояния добавляется каждые 15 секунд. При завершении модуль пишет
блоки `=== summary ===` и `=== verdict ===` с итогами запуска.

## Если что-то не работает

| Симптом                                       | Что проверить                                                                             |
| --------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Перечисленные хосты вообще не открываются      | Пока туннель не поднят, перечисленный хост недоступен. Найдите в логе `session up`.          |
| Лога нет                                       | Нет `awg.conf` или он не по тому пути, либо нет `boot2.flag` — модуль просто не запустился.  |
| Лог обрывается на `boot: waiting for the network` | Консоль так и не сообщила о работающем подключении. Проверьте Wi-Fi и перезагрузитесь.    |
| Повторяется `handshake ... attempt N`          | Endpoint недоступен либо ключи и параметры обфускации не совпадают с сервером.               |
| `proxy FAILED to bind :443`                    | Порт 443 уже занят другим модулем или приложением. Отключите его.                            |
| Через какое-то время хосты перестают открываться | Посмотрите `live=` в логе. При `16/16` таблица переполнена и растёт `full=` — сообщите об этом. |
| Hosts-файл пропадает после перезагрузки        | Некоторые загрузочные пакеты перезаписывают `default.txt`. На emuMMC используйте имя с ID.   |
| Сразу после сна какое-то время не работает     | Туннель восстанавливается сам, но Wi-Fi поднимается несколько секунд. Дайте полминуты, прежде чем перезагружать. |
| Большой промежуток между записями в логе        | Консоль спала; заморожены все процессы, включая наш. По краям промежутка стоят строки `power transition`.        |
| В доке во сне перечисленные хосты не работают  | Так и задумано. Отключите **Настройки → Режим ожидания → Поддерживать проводную связь в режиме ожидания**, см. ниже.                                |

Чтобы вернуть обычное поведение, удалите или переименуйте hosts-файл. Больше
ничего трогать не нужно.

## Ограничения

- Только TCP на порту 443. UDP и QUIC не передаются.
- Только имена хостов из hosts-файла. Остальной трафик не затрагивается.
- Один сервер на конфигурацию: без переключения на ходу и без подписок.
- Туннель разрывается при засыпании и восстанавливается после пробуждения; пока
  консоль спит, не работает ничего. Поддержание проводной связи во сне следует
  отключить — см. ниже.
- Нет оверлея и интерфейса; состояние пишется в лог.
- Скорость зависит от сервера, Wi-Fi и настроек туннеля. Текущая сборка
  выдаёт около 200 КБ/с.

### Сон и док

**Отключите настройку «Настройки → Режим ожидания → Поддерживать проводную связь
в режиме ожидания», пока пользуетесь этим модулем.**

Пока консоль спит, заморожены все системные модули, включая наш. Заметив переход
питания, модуль сам разрывает туннель — затирает ключи, закрывает сокет и после
пробуждения проводит новый хендшейк, — так что сессия не переживает молча тот
сон, за которым модуль не мог наблюдать.

Ничего при этом не утекает, при любом значении настройки. Перечисленные вами
имена по-прежнему разрешаются в `127.0.0.1`, и с замороженным модулем такие
соединения просто не устанавливаются, а не уходят мимо туннеля. Загрузки из
eShop не затрагиваются: они идут на серверы Nintendo, которые hosts-файл не
перенаправляет.

То есть сегодня настройка не стоит вам ничего, кроме несостоявшегося соединения,
и совет выше — рекомендация, а не требование. Он здесь для того, чтобы привычка
сложилась заранее. Когда трафик начнёт перехватываться на уровне сокетов, а не по
именам, замороженный модуль будет означать замороженную сеть для всей консоли — а
это ровно тот случай, когда консоль иначе бодрствовала бы и этой сетью
пользовалась.

## Сборка

Требуется devkitPro с devkitA64 и libnx.

Модуль запрашивает `pdm:qry` в `sys-amneziawg.json` — так он узнаёт, что
консоль уснула. Если убрать сервис из списка, больше ничего не сломается,
но сон перестанет замечаться, и туннель будет пересоздаваться только после
того, как умрёт его сокет.

```sh
export DEVKITPRO=/opt/devkitpro
make
```

Результат — `sys-amneziawg.nsp`. `make clean` удаляет результаты сборки.

В Windows собирайте из оболочки MSYS2, которая ставится вместе с devkitPro.
Если ассемблер не может создать временные файлы, задайте каталог явно, каждую
переменную отдельной командой:

```sh
export DEVKITPRO=/c/devkitPro
export TMPDIR=/c/Users/<пользователь>/AppData/Local/Temp
export TMP=$TMPDIR
export TEMP=$TMPDIR
make
```

Вендорный криптографический код выдаёт предупреждения компилятора.
Предупреждения из неизменённых файлов в `source/crypto/` ожидаемы и не являются
ошибкой проекта.

### Хостовый стенд

Ядро протокола собирается и для обычного компьютера — именно так оно и
разрабатывалось:

```sh
clang -std=gnu11 -Isource -o awg-host \
    source/awg_obf.c source/awg_config.c source/awg_rand.c \
    source/awg_noise.c source/awg_ipprobe.c source/main_host.c \
    source/crypto/*.c
./awg-host awg.conf
```

Стенд прогоняет тест-векторы BLAKE2s и X25519 из RFC, полный хендшейк между
инициатором и отвечающей стороной и транспортные пакеты — без консоли и без
обращения к сети.

| `source/awg_obf.c`      | Обфускация AmneziaWG: мусорные пакеты и шаблоны I1–I5.          |
| `source/awg_config.c`   | Разбор конфигурации `.conf`.                                    |
| `source/awg_session.c`  | Состояние сессии, таймеры, ротация ключей, keepalive.           |
| `source/awg_netif.c`    | Сетевой интерфейс lwIP поверх туннеля.                          |
| `source/awg_power.c`    | Замечает, что консоль уснула, читая журнал play-событий.        |
| `source/awg_proxy.c`    | SNI-прокси между сокетами консоли и lwIP.                       |
| `source/main_switch.c`  | Точка входа модуля, главный цикл и логирование.                 |

## Безопасность

`awg.conf` содержит действующий приватный ключ и даёт полный доступ к вашему
туннелю. Держите его только на доверенной карте и никогда не публикуйте — ни в
issues, ни в логах, ни в архивах. Он исключён через `.gitignore`.

Ключи сессии в лог не записываются.

**Но в лог попадает каждое имя хоста, прошедшее через туннель.** Это перечень
сайтов, которые открывала консоль, и он там потому, что модуль ещё отлаживается.
Просмотрите лог, прежде чем кому-то его отправлять, и удалите строки `proxy:`,
если не хотите делиться историей посещений. Лог переписывается заново при каждой
загрузке, так что в длинную историю он не превращается.
