# sys-amneziawg

[English](README.md) · Русский

Клиент AmneziaWG для Nintendo Switch в виде системного модуля Atmosphère.
Принимает конфигурацию, выгруженную из клиента AmneziaVPN, и направляет
выбранный трафик через этот туннель.

**Статус: бета (v0.0.1).** Протокол реализован полностью и проверен против
рабочего сервера. Трафик выбирается по именам хостов; системный перехват
сокетов не реализован.

## Что работает

- AmneziaWG 3.1: обфусцированный хендшейк, защита заголовков, мусорные
  пакеты, ротация ключей, keepalive
- Сетевой стек (lwIP) поверх туннеля
- Прозрачное проксирование перечисленных хостов, выбор по TLS SNI
- Измеренная скорость около 200 КБ/с; DNS резолвится внутри туннеля

## Что не работает

- Только TCP на порту 443. UDP и QUIC не передаются.
- Только имена хостов, перечисленные в файле `dns.mitm`. Остальной трафик
  не затрагивается.
- Один сервер на конфигурацию: без переключения на ходу и без подписок.
- Сон и пробуждение определяются, но не оптимизированы.
- Нет оверлея и интерфейса. Состояние пишется в лог-файл.

## Как это устроено

`dns.mitm` направляет перечисленные имена на адрес самой консоли. Модуль
слушает порт 443, читает имя хоста из TLS ClientHello, резолвит его через
туннель и передаёт соединение дальше. Для приложения это обычный сокет;
каждый байт идёт до узла AmneziaWG в зашифрованном виде.

## Требования

- Прошивка Atmosphère, рекомендуется emuMMC
- Конфигурация AmneziaWG с адресом узла в виде литерального IPv4
- Закреплённый за консолью адрес в настройках роутера

## Установка

1. Скопируйте `sys-amneziawg.nsp` на карту как:

   ```
   /atmosphere/contents/4200000000000D92/exefs.nsp
   ```

2. Скопируйте `toolbox.json` в:

   ```
   /atmosphere/contents/4200000000000D92/toolbox.json
   ```

3. Создайте пустой файл для автозапуска:

   ```
   /atmosphere/contents/4200000000000D92/flags/boot2.flag
   ```

4. Выгрузите конфигурацию AmneziaWG из клиента AmneziaVPN и положите её в:

   ```
   /config/sys-amneziawg/awg.conf
   ```

   Список принимаемых полей — в `awg.conf.example`. Поле `Endpoint` должно
   содержать литеральный адрес IPv4.

5. Узнайте адрес консоли в локальной сети (Настройки → Интернет → Состояние
   подключения) и закрепите его на роутере.

6. Скопируйте `hosts.example.txt` в `/atmosphere/hosts/emummc_XXXXXXXX.txt`,
   где `XXXXXXXX` — значение поля `id` из `/emuMMC/emummc.ini` без префикса
   `0x`. На sysNAND используйте `default.txt`. Замените в файле
   `192.168.1.10` на адрес консоли и перечислите нужные имена хостов.

7. Перезагрузитесь. Модуль ждёт 15 секунд, подключается и пишет
   `/config/sys-amneziawg/sys-amneziawg.log`.

## Проверка

В логе отражается состояние туннеля и каждое проксируемое соединение:

```
boot: network up
[  0s] session up (handshake #1, rekeys 0)
[  0s] proxy listening on :443
        proxy: raw.githubusercontent.com
[ 15s] up=14s tx=1137 rx=1952 | proxy conns=2 ok=1 fail=0 up=2KB down=1978KB
        rate 169KB/s (129 pkt/s) | tcp xmit=1137 recv=1952 drop=0
```

Если имя хоста перечислено в файле, а туннель не поднят, это имя становится
недоступным. Удаление файла возвращает обычное поведение.

## Безопасность

- `awg.conf` содержит действующий приватный ключ. Он исключён через
  `.gitignore`; не публикуйте его.
- В примере hosts-файла сохранена блокировка телеметрии Nintendo. Эти две
  строки удалять не следует.
- Ключи сессии в лог не попадают.

## Сборка

Требуется devkitPro с devkitA64 и libnx.

```sh
export DEVKITPRO=/opt/devkitpro
make
```

Хостовый стенд для тестов собирается отдельно:

```sh
clang -std=gnu11 -Isource -o awg-host \
    source/awg_obf.c source/awg_config.c source/awg_rand.c \
    source/awg_noise.c source/awg_ipprobe.c source/main_host.c \
    source/crypto/*.c
./awg-host awg.conf
```

Стенд прогоняет тест-векторы BLAKE2s и X25519 из RFC, полный хендшейк между
инициатором и отвечающей стороной, а также транспортные пакеты — без обращения
к сети.
